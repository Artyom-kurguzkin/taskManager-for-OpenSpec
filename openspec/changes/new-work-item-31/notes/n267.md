# Duplicate ids are repaired by renumbering the later item

When two work items or two notes hold the same id after a merge, the one created first keeps it and the other gets the next free id; the renumbering is logged as an event on the renumbered item.
It works for git merges today and for storage sync (#wi160) later, with no online source of truth needed. References from other items stay with the keeper, because which one they meant cannot be known.
