# Integrated chunks headers-first and publish-and-measure

headers-first (18 files from worktree chunk-am): the board reads the yaml once, tasks.md and the newest worklog time per item (events.log or note heads); proposals, notes, events and specs are read per item on demand into a 64-item LRU body cache (TaskManager/AppState/BodyCache.cs); the per-folder fingerprint got the racy rule (a folder touched within 20 ms of a read is re-read next time; injectable clock); `WorkItem.Revision` is lazy and memoized per folder look; new test class ReadingOnlyWhatIsNeededTests (6, 300 generated folders). Warm, busy machine, used demo of 1,364 files: file opens ~2,500 -> ~650, headers pass ~8.3 s -> ~2.0 s. Known leftovers from the chunk: 366 note heads still read for archived changes without events.log (a persisted stamp snapshot would remove them); the store's stale-write text record (`LastSeen`) is still unbounded; `board_list` computes revisions on demand.

publish-and-measure (4 files from chunk-an): dist-small.pubxml and dist.pubxml are ReadyToRun, uncompressed, native libraries beside the exe (the small profile copies Photino.Native.dll and WebView2Loader.dll into dist\); tests/startup-time.ps1 measures N hidden-desktop starts and prints the marks (median/max); StartupScriptTests (1). Its measurements before the load work landed showed cold-ish starts of 7 to 10 s for every build including R2R, i.e. the pre-window repository read dominated, not JIT; warm page-up has a ~2.15 s floor (WebView2 + window). Recommendation kept: framework-dependent R2R (32 MB) over self-contained (172 MB), no measured start gain.
