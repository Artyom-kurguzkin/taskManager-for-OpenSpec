# Hand-off: window first, headers first, the rest behind

What changed, in plain words: the window opens first with a grey outline of the board and the cards follow as soon as the item headers are read; git, the duplicate-id scan and worklog tracking run after that first paint; the board is built from each item's yaml header and task list only, with descriptions, notes, events and specs read when an item page needs them into a bounded cache; unchanged files are never parsed twice; the published exe is precompiled (ReadyToRun) and uncompressed, with the native libraries beside it; `tests/startup-time.ps1` measures every start the same way.

Timing on the integrated Debug build, medians of 5 hidden-desktop starts (ms from process start):
```
                 warm   cold-ish      before (the exe the owner ran on 20 Nov)
window-created    248       472       window up ~8000
first-render     1551      1862       first card 11700-16300
headers-read      747      2952
git-ready         982      3816
scan-done        1280      9151
page-up          2157      2170       page-up 2156 warm / 8056 cold-ish
```
R2R small publish (warm): window-created 176, first-render 1148, headers-read 475. page-up (~2.16 s) is the WebView2 floor for every build.

Merge fixes made during integration: a saved header sort of the list was lost when the rows arrived after the first paint (grid settings handed over once per grid instance, with a test); a git-ready change landing inside a page's reload window was dropped (`RepoPage` stamps now include the load/git state, with a test); the small publish profile no longer stops processes or writes dist\ unless it publishes into its own folder, and copies the native libraries from the resolved package files.

Regression: exploratory 52 of 52 on the integrated build. The full suite was green once on the integrated tree (1336 passed, 1 skipped, 1337) before the owner's test-suite sweep; the post-sweep run is in progress.

Leftovers: archived changes without events.log still cost one note-head read each (366 on the used demo); the store's stale-write text record is unbounded; Settings, Worklog, NotePage and ExaminePanel are not gated while a project loads; the pre-Blazor skeleton frame cannot be screenshotted over CDP; the duplicate scan takes 7-9 s cold-ish, after the first paint; reads and renders are not instrumented in the run log.
