# headers-first: read map before the change

Before: one folder parse opened .openspec.yaml 3 times, proposal.md, tasks.md, events.log (whole), the first 10 lines of every note, and hashed EVERY file for `Revision`. ItemsCache already skips unchanged folders by a name+size+mtime fingerprint (no racy rule). NotesCache.ForWorkItem read all notes of all items; item descriptions were re-read on every call; the events cache was version-keyed and unbounded.

A board card needs: the yaml header (title, status, label, priority, dates, contributors, agent stamps, features, lanes), tasks.md (subtask counts), spec folder names (from the directory listing, no open) and the "updated" stamp, which comes from the worklog (newest events.log line or note `created`; file mtimes only when there is no worklog). Bodies: proposal, notes, events list, spec text, revision hash.

Plan: Revision lazy and kept per folder look; yaml read once; proposal only when the header has no title; "updated" reads events.log for its times and a note head only when that note's file is not more than a day older than the newest event; racy rule; stamp-validated 64-item LRU body cache for description, events and per-item notes.
