# Cause and fix: the grid dropped its saved settings in the load's render gap

Cause: Radzen's grid decides `settingsChanged` in every parameter set ("is this object different from the one I hold") and applies `Settings` only in its first after-render. In the real WebView a render takes an IPC round trip before the after-render runs; the git-ready `Reproject` lands inside that gap, the list is drawn again with the same `gridSettings` object, the flag flips back to false and the saved header sort is never loaded. bUnit has no such gap (the new test `SavedHeaderSortSurvivesTheLoad` passes on the async flow alone) and HEAD rendered the list with git already ready, so neither showed it.

Fix (BoardPage.razor + .razor.cs): the grid's `LoadSettings` callback, which Radzen raises first in that after-render, hands each new grid instance a copy of `gridSettings` once; a copy counts as changed, so the saved sort, widths and filters are applied. `LoadGridSettings` keeps the copy as the page's own object afterwards, so later renders change nothing.
