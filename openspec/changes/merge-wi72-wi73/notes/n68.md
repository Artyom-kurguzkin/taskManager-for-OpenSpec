# 6 Nov: the guide now says how to create a work item

`openspec/REPO-TASKS.md` (v8) has a new section 3, "Create a work item". It says when something is a work item and when a subtask, then gives the steps: folder name, number, feature, status, specs or `skip_specs`, links (plan, dependencies, tests, commits, dates, notes), signing. A complete example item follows, with the rule for which heading a requirement goes under: ADDED when the main spec does not have it or does not exist, MODIFIED only when it does.

Why: an agent in another project wrote MODIFIED for a feature with no spec, which broke the archive; an agent in a third packed a whole plan into one item as 44 subtasks and put its spec under a different feature from the item's.

Checked two ways: the example's files are written by a test and read by the app and by `openspec validate --strict`; and a fresh agent on the cheapest model, given only the guide and "add these three tasks and one subtask", produced three valid work items with a dependency between two of them.
