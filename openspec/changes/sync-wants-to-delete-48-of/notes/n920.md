# Proposed: the board syncs through git; removals only by a logged event

Proposed (waiting for the owner's go): the board's history lives in `refs/rtm/board` of the project's own repository; a sync snapshots, fetches, merges with git's common ancestor and pushes, never touching the owner's branches or index. A file leaves the board only when a new board-level log says where it went (archived, merged, renamed); otherwise it is put back.

Correction to n918 and n919: the code writes no `deleted`, `moved` or `archived` event today, only `merged-from` in the new item. A merge removes its source folders and an archive moves a folder with no event in the place that empties; the plan adds those events. The two stopped agents' worktrees (sync-deletes, sync-fix) hold unmerged work built on the replaced rule.
