# Subtasks straight from the worklog

- A day's Shift-click menu has "Add subtask": an input opens in that day, Enter adds one and keeps the input open for the next, Esc or clicking away closes it.
- When a note's editor closes (in the feed or on the note page), every unticked `- [ ] text` line becomes a subtask and the feed shows "added subtask N"; the line stays in the note with " (created subtask)" appended, so it is made once. Ticked lines and code blocks are left alone. A toast says how many were created.
- An agent's `board_note` does the same and reports the new numbers.

Checked in the real app on the hidden desktop, light and dark: a note with two open boxes and one ticked made 2.10 and 2.11, the note kept its lines with the suffix, and two subtasks added from the menu showed in the feed and in Linked tasks.

Known: after an add the page takes about a second to repaint, so very fast typing of the next subtask can be partly lost. The note page has no test of its own for this.
