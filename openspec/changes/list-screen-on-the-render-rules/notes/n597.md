# Render-budget race: causes found and removed by design

Cause 1 (BoardPage.razor.cs OnAfterRenderAsync, subtasks branch): Radzen's CollapseRows/ExpandRows always call StateHasChanged on the grid, even with nothing to change, so the first draw of the list was followed by one more grid draw (RowRenders 48 -> 72 in a quiet run) queued after the render the test waited on. Fix: ask Radzen only when a row has to change (`change.Count == 0` returns). Test "Switching to the list draws the grid once and leaves no second draw behind" was red (Expected 48, Actual 72) and is green.

Cause 2 (OpenSpecStoreModule.StartWatching, real FileSystemWatcher): an event delivered later than the 1.5 s own-write window, plus the 300 ms debounce, raises Workspace.Changed -> Load() -> listVersion++, i.e. one Radzen draw (2 x 24 = 48 row renders) after a test took its before-count. A late event cannot be forced deterministically, so the cause is removed instead: seam `StoreState.RealWatcher` (default true, the app always has it), the render-budget test classes (ListRenderBudget, ListPills, BoardRenderBudget, PagesRenderBudget, SideMenuRenderBudget) set it false before opening the repository. Test "A render-budget test's store runs no real file watcher" was red (Actual FileSystemWatcher) and is green.

Not done on purpose: a global default of false for all tests. It broke UsingTheBoardTests.DuplicateIdsResolvedOnChange, which relies on the real watcher bumping the store version before its Notify(); several other tests call Workspace.Notify() after outside writes the same way and need OpenSpecStoreApi.Refresh() first. That is a follow-up that needs the full suite.
