# The app writes only valid YAML, and repairs the common hand-made breakage

- **Writing**: every string the app writes into a yaml file or a note's frontmatter is quoted when YAML needs it. YamlDotNet already quoted colons, hashes and quotes; it let through words it would read back as something else (yes, no, on, off, null, ~, numbers, a 7-character commit hash like 1e34567). Those are now quoted too, in the x-rtm block, the frontmatter and config.yaml's features. Everything the MCP tools take in goes through the same writers.
- **Reading**: a text value broken by hand (an unquoted colon or hash, e.g. `title: Fix: the thing #1`) is read as text with the warning "title on line 5 was not valid YAML and was read as text; the file is fixed on the next save"; the next save writes it quoted. Anything the repair cannot fix keeps the warning from the first half. An invalid features or testResults list in config.yaml no longer crashes either; adding a feature is refused rather than overwriting it.
- **Guide** (v14): quote a value with a colon, a hash or a leading special character, with the example.

Checked in the real app on the hidden desktop, light and dark: an item hand-written as `title: Fix: the thing #1` showed that title with the repair warning; renaming it wrote the title quoted and cleared the warning; a new item titled with a colon, a hash, brackets and both quote kinds came out quoted and read back identical. The OpenSpec CLI validates the files the app writes with such values.
