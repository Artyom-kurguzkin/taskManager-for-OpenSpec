# Merged from #wi96 No collisions, ever

## Why

Archiving #wi88 failed with "Archive '2026-11-05-new-work-item-13' already exists": the app had reused a change folder name that an archived change already held. The user's rule: the app resolves every collision itself; none ever reaches the user.

## What Changes

- A change folder name is never reused: creation, merge and split pick a name free across `openspec/changes/` and `openspec/changes/archive/` (any date prefix); archiving a name already archived today renames the folder first.
- Delta specs are repaired before the CLI archives: an ADDED requirement the main spec already has becomes a modification, a requirement listed twice in one delta is merged, a REMOVED requirement that is gone is dropped (stale MODIFIED blocks were already repaired).
- Note ids are unique across the repository, archived notes included; duplicates and file/frontmatter mismatches resolve themselves on read. Duplicate subtask numbers read as the next free number and are renumbered on write. Adding a subgroup that exists is a quiet no-op.
