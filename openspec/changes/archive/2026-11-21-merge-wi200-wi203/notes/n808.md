# Why a status cannot be deleted in the real board (#n795)

Reproduced in the hidden app (port 9633) on copies of both of the owner's open projects (repo-task-manager with Research in its config, portfolio with the built-in list), Settings, trash icon on every non-default status:

```
demo / Planned    : confirm "3 work items ... move to Backlog", Remove -> gone
demo / Confirmed  : confirm, Remove -> gone
demo / Blocked    : no items, gone at once
demo / Research   : confirm, Remove -> gone
demo / In Review  : confirm "26 work items ...", Remove -> NOT removed, toast:
   #wi163 did not move: Waiting on #wi160 "configurable external shared storage" - can't change status until it's resolved
portfolio / Planned, Confirmed, Blocked, In Review: all gone
```
Trash icon, confirm and the defaults list (only Backlog, In Progress, Completed) are right in both projects. The mechanism: `RemoveStatusMoving` moves each item with `SetStatus`, which refuses an item that waits on an unresolved dependency (it may only go to Blocked). In Review is the one status with many items (26), and some of them depend on an open item, so the first such item stops the removal. Worse, the items before it have already moved to Backlog (a partial move; 1 in this run), and the only sign is a short toast. Fix: deleting a status moves its items to the first status without the dependency gate (the status no longer exists, so the gate has nothing to protect), covered by a red test first.
