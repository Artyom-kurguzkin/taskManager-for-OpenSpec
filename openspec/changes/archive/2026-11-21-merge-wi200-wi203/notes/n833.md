# Column order bug: the mechanism

Reproduced over CDP (hidden app, port 9433, copy of this board, second demo repo without Research, window emulated at 1920 so every header is reachable). With two projects the shared header's columns (`section.col.head-only`, BoardPage.razor) had no `@ondrop`, so the drag script's drop "in front of Blocked" bubbled to the `.head-row` handler `DropColumn(HeadKeys, null)` = drop past the last column: Research went to the END and `Order` saved Research last ("stuck as the last one"). Left/Right did nothing either: `KeyDown` only moved selected columns for Up/Down in the list, and in a single project the board headers could not be Shift-clicked at all, so no arrow key could move them.

`BoardModel.Arrange` itself did honour `Order`, so the union builder, `MarkAbsent` and the config order were not the cause; the one gap there is that a status the saved `Order` does not hold yet went after everything the order holds instead of where the project lists put it (fixed too, status grouping only).
