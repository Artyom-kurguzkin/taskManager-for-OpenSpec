# Merged from #wi143 MCP server lives while the app runs

## Why

The board server started by the stdio shim runs from the dist folder for up to three idle hours, independent of the app, so a `dotnet publish` to dist fails with the exe in use and the user has to find and kill processes by hand. The user asked: "can you tie the server to the app gui running for now".

## What Changes

- The desktop app starts the board server when it opens (`--serve --parent <app pid> --idle 0`), and the server exits when that app process ends, closed or crashed.
- The stdio shim no longer starts a server. With no server running it answers every tool call with an error telling the agent to ask the user to open the Repo Tasks app, and it connects as soon as the app is up, without restarting the agent.
- Settings keeps its server chip; Start and Stop still work while the app runs.
- `--serve` without `--parent` keeps today's behaviour (idle exit), for headless use.
