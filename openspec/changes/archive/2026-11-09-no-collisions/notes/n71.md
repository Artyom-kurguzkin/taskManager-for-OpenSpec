# Note ids, subtask numbers and subgroups no longer collide

- A new note's id counts every note in the repository, archived ones too.
- Two notes with the same id sort themselves out when the app reads them: the newer one takes the next free id and its file is renamed. A note whose frontmatter id disagrees with its file name follows the file name.
- Two subtasks with the same number (agents appending at once) read as different numbers, and the file is renumbered on the next edit.
- Adding a subgroup that a column already has does nothing; dropping an item into an unknown subgroup creates it.

Checked in the real app: a seeded duplicate note became the next free id and shows in the item's change log.
