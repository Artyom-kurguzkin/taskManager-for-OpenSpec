# The item page is three views, and the worklog is a feed of notes and events

The work item page is rebuilt after the wireframe. Under the unchanged header there are three buttons, always all shown: Description, Worklog, Linked tasks.

- **Description**: the description as before (click to edit, paste images) and beside it a Related list of everything attached: the plan, linked documents, files and links from the description and the notes, and images.
- **Linked tasks**: three columns: Subtasks (everything the old subtasks tile did), Waiting on, Waiting on this. They stack in a narrow window.
- **Worklog**: one feed by day, newest first, each entry with who and when. Notes show their title, text and images; events are one line each (status: Planned → In Review, linked a commit, linked a test with its latest result, linked a document, ticked 1.2, waits on #wi12). Clicking a date folds the day. Shift-click a date: Add note (an editor in place; clicking outside saves; under an older day the note is dated that day), Link document, Link test, Link commit. Shift-click a note: Edit. Shift-click a linked commit, test or document: Unlink.
- **Events** are recorded from now on in `events.log` in the change folder, one line each with the time and who did it. Links older than the log still show: commits at their commit time, tests and documents under Linked earlier.
- **Documents** can be linked to an item (`x-rtm.docs`).
- **Agents**: what a tool call changes is logged under the agent's name; `board_get` returns the worklog; `board_update` takes `docs`; `board_note` needs no title. The server instructions and the guide (v13) tell agents to write an entry for what the tools cannot see, and give the `events.log` format for hand edits.

Gone: the bento tiles and tile focus, the linked commits and linked tests tiles, the per-test note button.

Checked in the real app on the hidden desktop, light and dark, 1280 and 1920 wide and narrow: the three views; a note added from today's menu and saved by clicking outside; a commit and tests linked and unlinked from the menus; a status change showing as an event; and an agent (through the MCP entry) changing the status, linking a document, adding a subtask and writing a note, all of which appeared in the feed under its name.

Not checked in the real app: Link document through the native file dialog (it cannot be driven on the hidden desktop); it is covered by tests through the typed-path fallback.
