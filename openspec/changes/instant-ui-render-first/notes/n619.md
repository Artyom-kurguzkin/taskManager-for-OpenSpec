# Decision

Render first, persist after: a page applies the command's result to its in-memory projection and renders before any disk write; the write runs on the thread pool, a failure puts the old projection back with a toast.
Every current source (Linear, Electric, Zero, the .NET 10 Blazor docs, web.dev) does it this way, and nothing in the shown result depends on the write succeeding first.
