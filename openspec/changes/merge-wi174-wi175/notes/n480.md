# Suite slowdown: cause

Same-machine comparison: the merged tree is not slower than HEAD (HEAD 2ee9a45 alone: 1060 passed in 3 m 32 s; merged tree: 1083 passed in 3 m 09 s; class totals are about equal). The 5 m 07 s run was CPU contention on the machine, and HEAD is 3x slower than this morning too. A thread-pool probe and dotnet-stack snapshots show the first ~30 s of every run use all 14 cores (pool latency up to 10.5 s). The two failures were wall-clock limits expiring in that window: a xunit `Timeout = 20000` on injected-clock sync work, and a bUnit wait queued behind ~115 grid renders per click ("Check count: 0", 144 renders). The only per-render cost added by the merge was WorkItemPage reading git state (HEAD file plus a walk of openspec/changes) in its markup on every render.
