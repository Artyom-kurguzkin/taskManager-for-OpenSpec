# Merged from #wi151 Server idle-exit test hangs when the machine is busy

## Why

On 10–11 Nov two agents ran the fast suite at the same time and one run took 7 h 28 m instead of about 2 minutes; another agent saw ServingTheBoardTests' idle-exit test hang in the full run while the same tests passed alone. A hanging test blocks the agent, holds its build folder and leaves processes behind.

## What Changes

- Find why the idle-exit test (and possibly the token/origin test, which also failed once at baseline) hangs or fails when other test runs or servers share the machine: shared port, shared RTM_HOME, a wait with no timeout, a process left running.
- Make the server tests isolated (own port and home per test) and bounded (every wait has a timeout), so the suite finishes in minutes even with parallel runs.
- Agents already run tests with `--blame-hang --blame-hang-timeout 5m` as a stopgap.
