# Bug 4 is a harness fault, not the product

Reproduced in the real app on the unmodified MAIN product code (status grouping): after an arrow key drops the header sort, a click on Updated sorts again (ascending, descending, none). In the "none" and "priority" groupings the Updated header sits at x=1369 in a 1280px window (the list scrolls sideways), so Set-GridSort clicked outside the window; that is the "did not reach 'none'" failure #n656 reports, not a Radzen state fault. Fix: Set-GridSort scrolls the header into view before the click; the subtask-tick step picks an item with an unticked subtask from the demo instead of 195.
```
probe, status grouping, MAIN code: after arrow: [] -> click1: ascending -> click2: descending -> click3: none
probe, none grouping, header scrolled into view, my code: same cycle
```
