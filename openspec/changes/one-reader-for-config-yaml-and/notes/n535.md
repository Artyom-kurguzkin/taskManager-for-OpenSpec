# One failure rule for config.yaml sections

A section of openspec/config.yaml that cannot be read reads as its default (no value) and is reported as a problem naming it (`ConfigSection<T>.Problem`); the read never throws and a locked file is `Unavailable`, which is no verdict on the section. A writer that edits a section it could not read is refused with that problem, so a hand-broken list is never written over.
Why: the 7 readers each failed differently (empty, built-in, throw, unreadable flag); the board shows the problem for lanes and statuses as a warning.
