# Hand-off: warn on close while files settle; a half-uploaded folder is held back and completed

Staged in the index, nothing committed. Plan: DevResources/plans/half-uploaded-folder-2026-11-27.md.

**What was built**
- A change folder with any file still inside the 10 s settle window is held back whole: nothing of it is uploaded, downloaded or removed that pass; a source folder moved into a held folder is held too. The state line reads "Waiting for N files to settle (folder …)" instead of "Nothing new" (chunks B, A).
- Closing the app while files settle shows "Files are still settling" naming the files and folder, with Wait and sync (waits, syncs the folder whole, closes; 5-minute cap), Close anyway, and Cancel (the dialog's standard button). The guard reads live file times, so it fires seconds after an in-app merge with no pass run (chunk A + fix a35f934).
- A storage folder this computer never synced is held back, not downloaded and not counted, while it is incomplete (notes but no .openspec.yaml, or a merged item whose sources are still live); the duplicate-note-id rule does not renumber a source's notes while a merged item names it. The computer that made the merge uploads the rest on its next sync; no new code was needed for that (chunk B).
- Settling entries from the last pass expire with the window; files the sync itself downloaded or replaced do not count as settling (fix cadeef3).
