# Measured: no layout gap between breadcrumb and column header

Measured over CDP in the real app (WT build of HEAD plus MAIN's uncommitted state, demo repo -Used), list grouped by status+priority, by status, and flat; 1280 and emulated 1920 wide, light and dark, dpr 1 / 1.25 / 1.5, scrolled at 250 and 777 px and swept every 137 px over the whole list. In every state: `.hdr-path` (breadcrumb strip) top 4, bottom 32, height 28, `position: sticky; top: 0`; first `thead th` top 32, bottom 68.7, height 36.7, `position: sticky; top: 28px`; **th top minus strip bottom = 0** everywhere. The rows scroll under the header and the first row whose bottom is below the header edge starts 5 to 39 px above it, as any row partly scrolled under a sticky header does; nothing is drawn between strip and header.

The owner's screenshot has the same geometry: breadcrumb text centre to the "Title" label centre is 32 px, which is strip 28/2 + th 36.7/2 = 32.3. So the "band" is the design: the breadcrumb sits in a 28 px strip and the header labels are centred in a 36 px cell. The CSS offset (`top: 28px`, shadow `-28px`) equals the strip's fixed `height: 28px`, and `ListHeaderBandIsCoveredOverTheWholeTableWidth` already pins them equal. I could not reproduce a gap or a row under the header in the current CSS; the screenshot's rows are 34 px against the CSS's 40 px, so it may come from a different build or zoom.
