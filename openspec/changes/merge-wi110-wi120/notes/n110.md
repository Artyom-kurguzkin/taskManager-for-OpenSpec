# The MCP server is built: tools, allocator, revision, hosts, guide

All five task groups are done and in the working tree, uncommitted.

- **Ids**: work-item and note numbers now come from one allocator that takes a file lock in the git common dir (`.git/rtm/`), looks at every worktree of the repository and remembers the last number it handed out. The app uses it too. Proof: two server processes in two worktrees created 40 items at the same moments, 40 different numbers.
- **Revision**: every work item has a 12-character revision (a hash of its files). `board_update` and `board_note` refuse a stale one and say the current one.
- **Tools**: a new `TaskManager.Mcp` library with `board_list`, `board_get`, `board_features`, `board_create`, `board_update`, `board_note`, `board_validate`. Every write is signed with the agent's name; Completed is refused; unknown test names come back as warnings; create and file edits run the pinned validator.
- **Hosts**: `TaskManager.exe --serve` (127.0.0.1, bearer token, Origin check, server.json, /health, /shutdown, idle exit) and `TaskManager.exe --mcp`, the stdio shim that finds, starts or replaces the server and falls back to serving in-process. The window-less exe reads and writes stdio fine, so no extra console exe was needed.
- **Guide**: REPO-TASKS.md v12 opens with how to detect the tools, turn them on and use them; CLAUDE.md, README and a `.mcp.json` at the root point at the shim. Settings shows the snippet.

Changed from the plan:
- The desktop app does not host the endpoint itself. The modules keep one current repository per process, so a tool call for another repository would switch it under the window. Settings shows the server's status and starts or stops it instead; the window sees an agent's writes through the file watcher.
- The shim tells the server its working directory and agent name with each call, because one server answers many shims; a plain HTTP call must name `repo`.
- The server's version includes the build time, so a rebuilt app replaces a running older server.
- Every tool call re-reads the repository instead of trusting the watcher.

Checked in the real app on the hidden desktop, light and dark: Start in Settings brought the server up, an item created through the shim passed the real validator and appeared on the board in Planned, a note by a second agent showed in its change log, Stop took the server down.

Left for the user: rebuild `dist/` (the committed `.mcp.json` points at `dist/TaskManager.exe`, which does not know `--mcp` yet) and open the app once so it rewrites this repository's REPO-TASKS.md to v12.
