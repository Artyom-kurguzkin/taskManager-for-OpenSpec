# Settings page tells the service; pull changes are followed

How a settings change made in this app is told from one that came from outside: the Settings page calls Workspace.AttachmentsFolderChangingHere(repo, newDir, moved) BEFORE it saves the folder, which records newDir as "seen" in the service (and in attachments-dir.txt in the project's app-data folder). Anything else that changes the folder (a pull) differs from the remembered one, so the sync loop follows it with MoveAttachments, once, before the next sync.
Why: the page is the single local write path and knows whether the files moved (Move) or stayed (Keep). Keep never moves later; the attachments sync's memory then starts over for the new folder as a first connection, so nothing is deleted in the storage.
