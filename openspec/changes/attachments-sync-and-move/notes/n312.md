# Chunk engine integrated

In the main tree: a storage view under a prefix (`BoardSyncApi.Under`), the `WholeFilesOnly` option (no text merge, the newer whole file wins, the loser to the trash), and files over the size limit skipped and listed in `TooLarge` (for the board's sync too). Large files are now hashed as a stream and re-read one at a time for upload. In the main tree, the sync, security, storage and merge classes:

```
Passed!  - Failed: 0, Passed: 270, Total: 270
```

Ceilings that remain: downloads are held in memory until applied (a first download of 300 files of 2 MB holds about 600 MB); one object is read whole, up to 64 MB. With whole files only a git operation in progress still pauses the sync when a git folder is given; the host passes none for attachments.
