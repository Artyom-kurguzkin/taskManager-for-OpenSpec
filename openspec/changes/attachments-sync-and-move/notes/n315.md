# Board sync state was not tied to the address; fixed

Finding with a failing test: the board's sync state (state/) was NOT tied to the storage address. After the address changed to a non-empty storage, files here that the new storage lacked were taken for deleted there and removed locally (the test lost its attachment and board file before the fix).
Fix in the host: state-address.txt in the project's sync folder records the address hash; before a sync of an approved setting, a different hash drops state.json, seen.json, pending.json, deletions.json and base/ of state/ and state-attachments/ (trash and backup stay). Test: "After the storage address changes, the board and the attachments both start as a first connection", now green.
