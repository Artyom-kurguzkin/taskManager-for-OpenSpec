# Flaky AgentChipAndMergedNote: a merge raced a note reader

Cause: not a render race. WorkItems.Commands.Merge copies each source's notes into the merged folder while the source folders still exist, so for a moment one note id lives in two folders. Any reader running then (the live Worklog, the watcher reload) goes through Notes.Queries.Load, "settles" the twin by renumbering to ++maxId and writes that file, which can be the id Merge had already picked for the merged-in note, so the merged-in note is overwritten and `GetForWorkItem(merged).Single(n => n.MergedFrom == 107)` finds nothing. Reproduced: a reader looping NotesApi.GetAll() during Merge lost the merged note in 35-45 of 60 runs; alone it never happens.

Fix: `OpenSpecStoreApi.StepsGate` (new lock, per store state). Merge holds it for all its steps; Notes.Queries.Cached and RepairDuplicateIds take it before their own lock, so a repair never sees a half-made merge. New test `MergeIsAtomicToNoteReaders` (red before, green after).
