# Path-keyed objects, seen set, refusal probe

Objects are keyed sha256(path, 0 byte, content hash); the manifest keeps the content hash. Staleness is decided by history, the local seen.json (no cap) and a refused object put; pending.json (written before the first put, removed after the state is saved) keeps an interrupted sync's own object from being read as proof of old content.
Why: no ceiling on remembered versions without extra requests. pending.json is only written when the host passes EditedInApp, so a host that never uses stale detection leaves the state folder untouched after a failed sync.
