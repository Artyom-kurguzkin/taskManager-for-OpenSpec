# Same-second names and when pruning runs

A path trashed twice in the same second keeps both copies: the second is named "<name> (2).<ext>"; the trash never overwrites. Pruning runs after every sync that went through (also a quiet one), never after Blocked or Failed, and only removes timestamp-named folders older than 30 days.
Why: the owner's rule is that the sync never erases a file; ponytail constant TrashKeepDays = 30.
