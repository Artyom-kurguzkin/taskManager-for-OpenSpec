# Old content is recognised without a history cap

Stale content from a git checkout is recognised from this computer's own uncapped memory of versions and from the storage refusing a "create only if absent" upload; objects are named by path plus content, and an event log changed outside the app is always union-merged.
The 20-version list in the manifest would let a week-old branch roll a busy file back for every computer. No extra requests: the check rides on the upload the sync makes anyway. Agreed with the owner on 12 Nov; sent to the trash agent as added scope.
