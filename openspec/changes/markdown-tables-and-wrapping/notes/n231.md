# The note editor is a keyed element of the feed loop

The in-place note editor is now a div with `@key="r.Key"` written directly in the `Entries` loop of Worklog.razor, not a call of the `Editor(...)` fragment, so Blazor keeps the same textarea when entries arrive above it.
Cause: the editor was an unkeyed fragment region among keyed sibling entries; a new entry above made Blazor build a new textarea, which lost focus and then fired focusout, closing the editor. A key can only reach siblings inside one render fragment, which is why the fragment call could not carry it. Reproduced on the hidden desktop with two `custom` events appended to events.log (marker lost, focus lost, editor closed); after the key all three hold. No refocus workaround.
