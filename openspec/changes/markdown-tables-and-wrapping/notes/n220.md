# Decision

Table edits go through document.execCommand("insertText") on a selection of the replaced range, with setRangeText + a dispatched input event as the fallback.
Why: execCommand keeps each edit as one step in the textarea's own undo stack (Ctrl+Z verified in the real app) and fires the native input event Blazor binds to; setRangeText alone is not undoable.
