# table-wait chunk started: cause of the TableHelperFollowsTheSideMenuEditor failure

Cause found in the test, not the product: `onScreen()` reads the `blazor:elementReference` attribute from bUnit's markup, but Blazor's RenderTreeDiffBuilder (case ElementReferenceCapture, a bare `break`) gives a render that only *keeps* the textarea no id, so bUnit writes `blazor:elementReference=""` from then on. Any second render before the check (the watcher/coalescing reload, Later's StateHasChanged) turns onScreen() into "" for good, while the attach (GUID from the creating render) is right; no further render means the WaitForAssertion never re-checks (Check count 1). Fix: the test remembers the id from the render that created the textarea (OnMarkupUpdated) and settles with `await log.InvokeAsync(() => {})` instead of waiting on renders; same flaw fixed in NoteEditorGrowsWithItsText.
