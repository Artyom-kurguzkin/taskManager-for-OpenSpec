# Decision

The index is the truth: the cache is kept current by the app's own writes (write-through) and by the watcher, verified by size+mtime stamps (one directory listing, no file reads unless a stamp differs) instead of a blanket refresh per tool call, patched per item for notes and feed, rebuilt once per burst of writes, and persisted per repository so a start paints from it and verifies behind.
Why: every write currently rebuilds the whole cache and every tool call re-reads the repository (one to four seconds on a real board); the research (local/research/fast-startup-2026-11-20.md Part C) shows Obsidian, git and VS Code all use a stamped index updated from events.
Rules out: the NTFS change journal or any platform-specific change feed (must run on macOS and Linux); SQLite for now (a JSON index file suffices at this scale).
